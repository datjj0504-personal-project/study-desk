## F. Known Issues and Technical Decisions

- Wails CLI is not installed. `wails doctor`, `wails dev`, and `wails build` were never run; generated assets in `build/` (icon, Windows manifest) and `frontend/wailsjs/` do not exist. The exe was built with plain `go build`.
- `frontend/dist` must exist for `go build` to compile (`//go:embed`). It is git-ignored; run `npm run build` in `frontend/` first. Wails does this automatically.
- No Go or frontend tests exist.
- Rendered UI has not been visually verified.
- Root `package.json` is a minimal stub with `wails` scripts only.
- SQLite driver choice is open (see [database design](../docs/02-design/database-design.md)).
- Decisions: [ADR 0001](decisions/0001-use-wails-go-react-sqlite.md). The Go package at the repo root is `main` (Wails convention).
- Deferred: client-side routing library (simple state-based navigation for now); theme switching.

## G. Next Recommended Task

**P1-004: Establish frontend-to-Go communication and error handling.**

- **Why next:** the shell exists, but nothing proves the Go/UI binding path, and it is required by every later feature. It should also be done with the real Wails CLI so bindings are generated, not invented.
- **Prerequisites:** install the Wails CLI (`go install github.com/wailsapp/wails/v2/cmd/wails@latest`), confirm `wails doctor` passes, and get user approval for the install.
- **Steps:**
  1. Run `wails dev` once to confirm the existing project works with the CLI and generates `frontend/wailsjs/`; fix any config mismatches (e.g. missing `build/` assets).
  2. Add one small bound method on `App` (e.g. `AppInfo()` returning name and version).
  3. Wrap it in `frontend/src/services/` and show the result and any error state on the dashboard.
- **Acceptance:** the UI displays data from Go; a forced error shows a visible message; `go vet`, `npm run build`, and `wails build` succeed.
- **Validation:** `gofmt -l .`, `go vet ./...`, `cd frontend; npm run build`, `wails build`, then launch `build/bin/studydesk.exe`.
